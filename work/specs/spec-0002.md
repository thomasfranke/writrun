# spec-0002 — Reflect every task a pull request carries

## Scope

The machinery that follows a pull request learns to read the full task
set from the `[TASK-NNNN]` tags in the PR title, with the branch-name
marker as fallback: mirrors follow review for every carried task, and
the in-flight report names them all.

In scope: `reflect_progress.sh`, `writrun-progress.yml` (the title
handed through the environment), `list_tasks.sh` and its
`WRITRUN_PR_LIST` contract. Out of scope: the checks — state and deltas
already judge per file and per union — and the mirror lifecycle rules
themselves.

## Steps

1. `writrun-progress.yml`: pass the PR title to `reflect_progress.sh`
   via the environment — it is a fork's text, never inline-interpolated.
2. `reflect_progress.sh`: parse the run of `[TASK-NNNN]` tags leading
   the title, one bracket each and no separator; when tags exist they are the task set,
   otherwise the branch marker resolves as today; move every resolved
   task's mirror exactly as one is moved now.
3. `list_tasks.sh`: extend the PR listing (the `gh` query and
   `WRITRUN_PR_LIST`) with the title; report in flight every task tagged
   in any open PR, branch marker as fallback.
4. A tag naming no task on disk is reported and skipped, never a crash.

## Acceptance criteria

- When an open PR's title opens with `[TASK-0004][TASK-0005]`, the system
  shall move both mirrors to `status:in-review`.
- When a title carries tags, the branch marker shall not add a task the
  title does not name.
- When a title carries no tag, the system shall resolve the branch
  marker exactly as today.
- When a merge completes several carried tasks, the system shall close
  each task's mirror.
- When an open PR tags a task, `list_tasks.sh` shall report that task as
  in flight, whatever the branch is named.
- When a tag names no task on disk, the system shall say so and
  continue.

## Edge cases

- A tag-shaped string appearing after the leading run — prose, not a tag.
- Duplicate tags in the run.
- A hostile fork title — environment only, never interpolated.

## Tests required

One case per acceptance criterion, in the reflect and list-tasks suites.

## Definition of Done

- `make tests` green, including the new cases.
- `make template-sync` changes nothing beyond the synced copies.
- No permanent doc touched.

## Outcome

Built as planned. `writrun-progress.yml` passes `PR_TITLE` through the
environment; `reflect_progress.sh` parses the leading run of tags into a
task set and moves every mirror in it, falling back to the branch marker
when the title carries none; `list_tasks.sh` takes the title in its PR
listing and reports every tagged task in flight. The suite went from 144
to 150 case files.

The script's shape changed more than the steps implied: it used to
resolve one task and then act, so the whole per-task move moved into a
`reflect_one` function the set is looped over. `ISSUES` and the merged
PR's file list are fetched once and reused across the loop rather than
per task.

Three divergences:

- **A subshell ate the first fix.** Resolving a branch through its spec
  needs to carry back *how the queue writes that id* — `task_ref` is the
  authority when the task's own file is absent. Setting a global from
  `num_from_branch` looked right and silently did nothing: the function
  is called in a command substitution, which runs in a subshell. It now
  returns both values on one line. Six existing cases failed on this and
  named it precisely, which is what they are for.
- **`PR_TITLE` is optional, and `WRITRUN_PR_LIST` gained a fourth
  field.** Both stay backward compatible on purpose: a pull request
  opened before the tag convention has no tags to read, and its branch
  must keep resolving exactly as it did.
- **One message changed.** "Branch X names no task" became "Neither the
  title nor branch X names a task", since the title is now consulted
  first. The case asserting the old wording was updated; the behaviour —
  reflect nothing, touch the forge not at all — is unchanged.

Also renamed the PR-listing loop's `title` variable to `ptitle`: it
shadowed the `title()` function used further down. Bash keeps the two
namespaces apart so nothing was broken, but the next reader should not
have to know that.
