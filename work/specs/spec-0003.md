# spec-0003 — Title mirror Issues by task tag

## Scope

The mirror's title moves from `task-NNNN — <title>` to
`[TASK-NNNN] <task title>`, and every place that finds a mirror by its
title moves with it.

In scope: `mirror_issues.sh` (minting, duplicate detection, the
foreign-mirror guard), `reflect_progress.sh` (mirror lookup), and a
one-time retitle of the mirrors that already exist. Out of scope: labels
and their lifecycle — `status:*` and `writrun:task` are untouched — and
the mirror body.

## Steps

1. `mirror_issues.sh`: mint new mirrors titled `[TASK-NNNN] <task
   title>`; match existing mirrors by the tag, still recognising the old
   `task-NNNN ` prefix so pre-rule mirrors are found, not duplicated.
2. `reflect_progress.sh`: resolve a task's mirror by the tag, with the
   same old-prefix fallback.
3. In the implementing change, retitle the existing mirrors to the tag
   form — the Issue is a projection, so retitling it rewrites no
   authority.

## Acceptance criteria

- When a merged task gains its mirror, the system shall title it
  `[TASK-NNNN] <task title>`.
- When the machinery looks a mirror up and only an old-form title
  exists, the system shall find it and shall not create a duplicate.
- When a foreign Issue carries a tag-shaped title for an id the queue
  does not own, the foreign-mirror guard shall keep refusing to touch
  it.
- When the implementing change lands, every existing mirror shall carry
  the tag-form title.

## Edge cases

- A task title that itself contains a bracketed tag-shaped string.
- Case: the tag is uppercase, the file id lowercase — lookups map one to
  the other.

## Tests required

One case per criterion, in the mirror and reflect suites.
