# spec-0001 — Name task and spec files by id and subject

## Scope

Every writer and reader of a queue file's name moves to the documented
shape `task-NNNN-<subject>.md` / `spec-NNNN-<subject>.md` — four-digit
id plus a two-or-three-word kebab-case echo of the title — while still
accepting the bare-id files that predate the rule, because a queue file
is never renamed.

In scope: `new.sh` (the writer, both subcommands),
`check_front_matter.sh` (canonical shape), `mirror_issues.sh` (queue-file
detection), `reflect_progress.sh` and `check_state.sh` (id-to-file
resolution), the `writrun-create-task-and-spec` SKILL.md, and the
template mirror. Out of scope: any rename of an existing queue file.

## Steps

1. `new.sh`: mint four-digit ids (`task-0006` follows `task-0005`,
   `spec-0003` follows `spec-0002`), derive the slug from the title,
   write `work/tasks/task-NNNN-<subject>.md` /
   `work/specs/spec-NNNN-<subject>.md`; keep finding the highest
   existing id across both filename shapes.
2. `check_front_matter.sh`: `id` agrees with the filename's
   `task-NNNN` / `spec-NNNN` prefix — a bare-id file still matches
   exactly.
3. `mirror_issues.sh`: recognise bare-id and slugged queue files alike,
   tasks and specs both.
4. `reflect_progress.sh`: resolve a task or spec id to its file by
   prefix, no longer by `${id}.md` alone.
5. `check_state.sh`: resolve `spec_ref` entries to slugged spec files by
   prefix (today: `find -iname "${ref}.md"`).
6. `list_tasks.sh`: prove it tolerates both shapes (it reads front
   matter, so likely no change — the suite says so either way).
7. Update `writrun-create-task-and-spec/SKILL.md` to the new shape and
   run `make template-sync`.

## Acceptance criteria

- When `new.sh task` runs with a title, the system shall write
  `work/tasks/task-NNNN-<slug>.md` whose four-digit id equals the
  filename's prefix — and `new.sh spec` the same for
  `work/specs/spec-NNNN-<slug>.md`.
- When the queue holds bare-id and slugged files together, `new.sh`
  shall mint the next id above the highest, whichever shape holds it.
- When `check_front_matter.sh` reads a slugged queue file whose id
  equals the filename's prefix, the system shall pass it.
- When a queue file's id disagrees with its filename's prefix, the
  system shall fail it.
- When a pull request adds a slugged task file, `mirror_issues.sh` shall
  create its mirror Issue as it does for a bare-id file.
- When `reflect_progress.sh` resolves a carried task, the system shall
  find the task's file with or without a slug.
- When `check_state.sh` resolves a `spec_ref` entry to a slugged spec
  file, the system shall find it by its id prefix.

## Edge cases

- A slug containing digits must never be read as part of the id.
- Two files sharing an id prefix (`task-0006-a.md`, `task-0006-b.md`)
  are a structural error the canonical check names.
- The bare-id fossils this queue already holds stay valid forever.

## Tests required

One case per acceptance criterion, each in the owning script's existing
suite directory.

## Definition of Done

- `make tests` green, including the new cases.
- `make template-sync` changes nothing beyond the synced copies.
- No task or spec file renamed.
